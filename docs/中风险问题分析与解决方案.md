# 中风险问题分析与解决方案

## P0 - 并发安全（可能导致死锁或数据竞争）

### 1. globalStore 竞态条件
**文件**: `internal/storage/store.go`
**行号**: 165-175
**问题描述**: `SetGlobalStore()` 和 `GlobalStore()` 无锁保护，并发访问可能读到 nil
**可能风险**: 初始化过程中的竞态条件可能导致 nil 指针解引用
**严重程度**: 高

**解决方案**:
使用 `sync.RWMutex` 保护全局 Store 的读写

```go
var (
    globalStore *Store
    storeMu    sync.RWMutex
)

func SetGlobalStore(s *Store) {
    storeMu.Lock()
    defer storeMu.Unlock()
    globalStore = s
}

func GlobalStore() *Store {
    storeMu.RLock()
    defer storeMu.RUnlock()
    return globalStore
}
```

### 2. clients map 竞态
**文件**: `pkg/alist/client.go`
**行号**: 142-156
**问题描述**: 检查客户端存在到创建客户端之间存在窗口期，多个 goroutine 可能同时创建同一个 key 的客户端
**可能风险**: 多个相同的客户端被创建，后一个覆盖前一个，可能导致连接泄漏或状态不一致
**严重程度**: 高

**解决方案**:
使用双重检查锁定模式，在锁内进行二次检查

```go
func GetClient(url, username, password, token string) (*AlistClient, error) {
    // 确保url有协议前缀
    if url != "" && !startsWith(url, "http://") && !startsWith(url, "https://") {
        url = "https://" + url
    }
    url = trimRight(url, "/")

    key := url + ":" + username

    // 快速路径：已有客户端直接返回（读锁）
    clientsMu.RLock()
    if client, exists := clients[key]; exists {
        clientsMu.RUnlock()
        return client, nil
    }
    clientsMu.RUnlock()

    // 创建新客户端（写锁）
    clientsMu.Lock()
    defer clientsMu.Unlock()

    // 二次检查：可能在等待锁期间被其他协程创建
    if client, exists := clients[key]; exists {
        return client, nil
    }

    client, err := newAlistClient(url, username, password, token)
    if err != nil {
        return nil, err
    }

    clients[key] = client
    return client, nil
}
```

### 3. daemon AddTask/RemoveTask 与 loadPendingTasks 潜在死锁
**文件**: `internal/modules/alistsync/daemon.go`
**行号**: 52-63, 96
**问题描述**: `loadPendingTasks()` 持有 `activeMu.Lock()` 期间，如果 `AddTask()` 或 `RemoveTask()` 被调用会死锁。当前使用中 `loadPendingTasks()` 只在首次启动前调用，但设计上存在隐患
**可能风险**: 如果启动时序改变或在其他地方调用，可能导致死锁
**严重程度**: 高

**解决方案**:
`loadPendingTasks()` 只在 `loop()` 首次启动前调用，此时没有其他协程调用 `AddTask()`/`RemoveTask()`，但为安全起见，应确保调用顺序或在锁内做更细粒度的操作

## P1 - 事务与状态问题

### 4. SaveSnapshot DELETE 后 INSERT 失败丢数据
**文件**: `internal/storage/store.go`
**行号**: 378-402
**问题描述**: `SaveSnapshot` 先 DELETE 再 INSERT，如果 INSERT 失败，快照数据丢失
**可能风险**: 快照保存失败导致上次快照数据丢失，影响增量同步判断
**严重程度**: 高

**解决方案**:
使用 `INSERT ... ON CONFLICT DO UPDATE` 原子操作，避免先删后插的数据丢失

```go
func (s *Store) SaveSnapshot(configID int64, entries []SnapshotEntry) error {
    tx, err := s.db.Begin()
    if err != nil {
        return err
    }
    defer tx.Rollback()

    // 先尝试 UPDATE，失败再 INSERT
    for _, e := range entries {
        result, err := tx.Exec(`UPDATE alist2strm_snapshots SET size=?, modified=?, sign=?
            WHERE config_id=? AND path=?`, e.Size, e.Modified, e.Sign, configID, e.Path)
        if err != nil {
            return err
        }
        affected, _ := result.RowsAffected()
        if affected == 0 {
            _, err = tx.Exec(`INSERT INTO alist2strm_snapshots (config_id, path, size, modified, sign)
                VALUES (?, ?, ?, ?, ?)`, configID, e.Path, e.Size, e.Modified, e.Sign)
            if err != nil {
                return err
            }
        }
    }

    return tx.Commit()
}
```

## P2 - 安全风险

### 5. Debug 日志输出敏感信息
**文件**: `pkg/alist/client.go`
**行号**: 372-385
**问题描述**: 在 `FSList` 中获取文件下载链接时，日志记录了完整的文件名和 RawURL，其中可能包含签名信息
**可能风险**: 如果日志级别设为 Debug，敏感的下载链接和签名会被记录
**严重程度**: 中

**解决方案**:
对敏感信息进行脱敏处理

```go
c.logger.Debugf("[DEBUG]   RawURL: %s", maskURL(result.Content[i].RawURL))

func maskURL(url string) string {
    if len(url) > 50 {
        return url[:50] + "..."
    }
    return url
}
```

### 6. Web 缺少安全头部
**文件**: `internal/web/server.go`
**行号**: 26-33
**问题描述**: HTTP Server 没有配置任何安全相关的头部（如 `X-Content-Type-Options`、`X-Frame-Options`、`Content-Security-Policy` 等）
**可能风险**: 容易受到 XSS、点击劫持等攻击
**严重程度**: 中

**解决方案**:
添加安全中间件

```go
// 在 newRouter 后包装安全中间件
handler := securityMiddleware(s.newRouter())
s.httpServer.Handler = handler

func securityMiddleware(h http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        w.Header().Set("X-Content-Type-Options", "nosniff")
        w.Header().Set("X-Frame-Options", "DENY")
        w.Header().Set("X-XSS-Protection", "1; mode=block")
        w.Header().Set("Content-Security-Policy", "default-src 'self'")
        h.ServeHTTP(w, r)
    })
}
```

## P3 - 状态同步

### 7. loadPendingTasks 内存与磁盘状态不同步
**文件**: `internal/modules/alistsync/daemon.go`
**行号**: 96-106
**问题描述**: `loadPendingTasks()` 加载任务到 `activeTasks` map 后，在 `pollTasks()` 中遍历该 map 进行处理。如果程序在加载后崩溃或被强制关闭，内存中任务状态可能比磁盘新
**可能风险**: 程序重启后任务状态回退，导致重复处理
**严重程度**: 中

**解决方案**:
这是预期行为（内存状态优先于磁盘），在 `loadPendingTasks` 日志中说明即可

## 一、严重（C：挂死 / 崩溃 / 数据破坏）

### C-1 Alist 客户端自锁死锁（密码登录模式必现）

- **位置**：`pkg/alist/client.go:196-232`（getToken）
- **描述**：`getToken()` 在持有 **写锁**（`c.tokenMu.Lock()`）期间调用 `authLogin()` → `doRequest()` → `makeHeaders()` → `getToken()` 再次 `RLock()`。Go 的 `sync.RWMutex` 不可重入：同一 goroutine 写锁内再 RLock 会永久阻塞。
- **触发条件**：配置使用 username/password 认证时（`tokenExp` 初始为 0，首次调用即判定过期），`newAlistClient → syncMe` 第一步就死锁。使用静态 token（`tokenExp=-1`）不受影响。
- **影响**：任务 goroutine 永久挂起，TrackRun 无法结束，cron 任务堆积。
- **修复方案**：
  1. 将 `authLogin` 移出锁外：写锁内仅做"标记刷新中"，释放锁后再登录，拿回锁后二次检查并写入新 token；
  2. 或改为单把 `sync.Mutex` 串行化 getToken，去掉读写锁升级逻辑；
  3. 补充一个带 httptest 假 Alist 服务端的登录流程测试，防止回归。

### C-2 ani2alist 未检查类型断言导致 panic，且后台 goroutine 无 recover，进程整体崩溃

- **位置**：
  - 断言点：`internal/modules/ani2alist/ani2alist.go:122`（`additionDict["url_structure"].(string)`）
  - 无 recover 的执行环境：`internal/web/handler_modules.go:78`（`go entry.RunFunc()`）、`cmd/autofilm/main.go:127`（裸 `cron.New(cron.WithSeconds())` 未挂 Recover 链）、main.go 各 `go runXxx()`
- **描述**：新建 UrlTree 存储时 Addition 为空字符串，`additionDict` 为空 map，断言 nil 直接 panic。panic 发生在无 recover 的 goroutine / cron 任务中，整个进程退出。
- **影响**：一次异常数据即导致服务整体崩溃；其他模块的潜在 panic 同样致命。
- **修复方案**：
  1. ani2alist 改用安全断言：`raw, _ := additionDict["url_structure"].(string)`；
  2. `cron.New` 增加 `cron.WithChain(cron.Recover(core.GetLogger()))`；
  3. main.go 各 RunFunc 与 handleRunModule 的 goroutine 内加 `defer recover()` 统一兜底并记录 error 日志/告警。

### C-3 AlistSync RetryDaemon 每次 Run 都重启轮询循环

- **位置**：`internal/modules/alistsync/alistsync.go:87`（每次 Run 调 `daemon.Start(ctx)`）；`internal/modules/alistsync/daemon.go:40-43, 65-87`
- **描述**：`loop()` 只在 stopCh / ctx.Done 时退出，而 ctx 为 `context.Background()`，永不结束。第二次 cron 触发后同一 daemon 出现两个 ticker 循环并发轮询同一批任务。
- **影响**：goroutine 泄漏、重复 TaskRetry/FSPut 提交、task 对象并发读写竞态。
- **修复方案**：RetryDaemon 增加 `started atomic.Bool` 守卫，`Start()` 幂等；或 Alissync.Run 内先判断再启动。

### H-1 ModuleEntry 并发数据竞争（4 处）

| 子项 | 位置 | 描述 |
| --- | --- | --- |
| H-1a | `internal/web/registry.go:75-98, 107-118` | `List()/ListByType()` 在 **RLock 下写** `entry.NextRun`（updateNextRun），两个并发请求即互相竞争；handler_modules.go:23 还在锁外拷贝读取 |
| H-1b | `internal/web/handler_modules.go:100` | toggle 无锁写 `entry.Enabled`，与 cron RunFunc（filemove main.go:532 读该字段）及 List 序列化并发冲突 |
| H-1c | `cmd/autofilm/main.go:28, 478` | 全局 `alistsyncDaemons = append(...)` 在并发 RunFunc 中无锁操作全局 slice，且只增不减（内存泄漏） |
| H-1d | `cmd/autofilm/main.go:166-206` | reload 协程重新赋值局部变量 `cronScheduler`，与主协程退出路径的读取构成变量级数据竞争 |

- **修复方案**：
  - updateNextRun 的写入纳入 registry 写锁（或在 List 快照中计算 NextRun，不改 entry 本身）；
  - Enabled 改为 `atomic.Bool` 或经 registry 方法加锁切换；
  - alistsyncDaemons 加 mutex 保护，或改为 daemon 自注册到带锁的全局容器；
  - reload 协程与主流程通过 mutex/channel 共享 scheduler（封装成 struct）。

### H-2 备份/恢复丢失 FileMove 配置

- **位置**：`internal/storage/admin.go:255`（ExportBackup 类型列表）、`admin.go:278-314`（ImportBackup 同样只认 4 类）
- **描述**：备份导出/导入的类型列表为 `alist2strm/ani2alist/libraryposter/alistsync`，漏掉 `filemove`。换机恢复后 FileMove 配置全部丢失。
- **修复方案**：两处列表统一加入 `filemove`，建议抽成共享常量 `backupModuleTypes`。

### H-3 模块启停（toggle）不持久化

- **位置**：`internal/web/handler_modules.go:90-106`
- **描述**：toggle 只修改内存 entry，重启或配置热重载（reg.Clear 后重建）后状态复原，与 README "模块启停" 承诺不符。
- **修复方案**：toggle 时同步写回 SQLite（如 module_configs payload 中更新 `enable` 字段，或新增独立开关表）；重建 cron 后按持久化状态恢复。

### H-4 大写扩展名文件被静默跳过

- **位置**：`internal/extensions/exts.go:7-42`（ext 表全小写）+ `pkg/alist/client.go:60-67`（Suffix 保留原始大小写）
- **描述**：`MOVIE.MKV`、`.SRT`、`.JPG` 等大写扩展名在 `processFileExts[path.Suffix()]` 匹配不到，文件被静默忽略（全量/增量模式一致）。
- **修复方案**：`AlistPath.Suffix()` 返回前 `strings.ToLower`；同时 `getLocalPath/getLocalPathFromRemote` 保持一致（统一小写化后截断替换）。补一条大写扩展名的单元测试。

## 三、中（M：性能 / 安全 / 健壮性）

### M-1 全量扫描 N+1 请求且限流失效

- **位置**：`pkg/alist/client.go:375-397`（FSList 对每个文件串行 FSGet）；`internal/modules/alist2strm/alist2strm.go:262-267`（SetRateLimit 仅增量模式调用）
- **描述**：列出目录时对每个文件额外发一次 `fs/get`，请求量翻倍且串行；`qps_limit` 配置在全量模式下被完全忽略。
- **修复方案**：
  1. FSList 增加参数控制是否预取 RawURL（AlistURL 模式下 list 已含 sign 可跳过；RawURL 模式才按需 fs/get）；
  2. runFull 也应用 `calcQPS()` 设置限流。

### M-2 replacePrefix 路径前缀边界 bug

- **位置**：`internal/modules/alistsync/sync.go:153-158`
- **描述**：`strings.HasPrefix(path, oldPrefix)` 不校验路径段边界，`src=/movies` 会错误匹配 `/movies2/file`，目标被写到 `/backup2/file`。
- **修复方案**：比较时给 oldPrefix 补尾 `/`（oldPrefix 为 `/` 时除外）：`path == oldPrefix || strings.HasPrefix(path, oldPrefix+"/")`。filemove.go 中 `remotePathWithin` 已有正确实现可参考对齐。

### M-3 凭据泄入访问日志

- **位置**：`internal/web/auth.go:26`（bearerToken 回退取 query token）、`internal/web/handler_health.go:22-25`（GET /api/alist/test 密码走 query）、`internal/web/router.go:25`（chi middleware.Logger 记录完整 URL）；另 auth.go:35 token 比较非常量时间。
- **修复方案**：
  1. 移除 query token 回退（WebSocket 改用子协议 header 或首条鉴权消息）；
  2. alist/test 仅保留 POST body 形式；
  3. Logger 换成自定义 formatter 脱敏 query；
  4. token 比较改 `subtle.ConstantTimeCompare`。

### M-4 默认部署零鉴权窗口 + /metrics 公开

- **位置**：`docker-compose.yml`（0.0.0.0 且 token 注释掉）+ `internal/web/auth.go:54-58`（无用户且无 token 时放行 admin）+ `internal/web/router.go:28`（/metrics 不经鉴权）
- **描述**：bootstrap 创建管理员之前整套 admin API 对外裸奔；/metrics 泄露模块名、运行次数等信息。
- **修复方案**：/metrics 移入鉴权组或增加独立 metrics token；文档强调公网必须先设 AUTOFILM_WEB_TOKEN；可选：无用户且无 token 时只允许 `/api/auth/*` 与 SPA 静态资源。

### M-5 下载中断留下脏文件、重试不清理

- **位置**：`pkg/httpclient/client.go:186-245`
- **描述**：重试直接 `os.Create(filePath)` 截断旧文件；最终失败仍留下半截文件；重试间 `time.Sleep` 不响应 ctx 取消。
- **修复方案**：下载到 `filePath+".part"` 临时文件，成功后 rename；sleep 改 select ctx.Done。

### M-6 日志接口全量读入内存

- **位置**：`internal/web/handler_logs.go:141-160`
- **描述**：tailLogFile 为取末尾 N 行把整个日志文件读入内存，大日志（数百 MB）会撑爆内存。
- **修复方案**：从文件末尾按块反向扫描（seek 到 end，按 4KB 块向前找换行符），凑满 n 行为止。

### M-7 单条损坏配置拖垮整个模块类型加载

- **位置**：`internal/storage/store.go:85-93`（Decrypt/Unmarshal 失败整体返回错误）+ `cmd/autofilm/main.go:240-247`（出错返回空列表）
- **描述**：任一 payload 解密失败，该类型全部模块都不加载，且只有一行启动日志提示。
- **修复方案**：ListModuleConfigs 改为逐条容错：坏条目记录告警（含 cfg_id）后跳过；启动日志明确指出被跳过的配置。
